주식 자동매매 시스템 전체 동작 원리 및 API 통신 매커니즘

프로그램이 켜진 후 종료될 때까지의 거시적인 흐름(파이프라인)과 각 단계에서 발생하는 데이터 통신(GET/POST)의 세부 원리를 알아봅시다.

제 1부: 자동매매 파이프라인 (거시적 흐름)

1 인가 및 인증 (Authentication)

프로그램이 증권사 서버에 접근하기 위해 가장 먼저 출입증(Access Token)을 발급받는 단계입니다.

  • 동작: App Key와 Secret Key를 증권사 서버로 전송 (POST 요청)
  • 결과: 유효기간이 있는 토큰을 발급받아 프로그램 메모리에 저장
⬇

2 기초 데이터 수집 (Data Fetching)

매매 결정을 내리기 위해 현재 시장 상황과 내 지갑 사정을 파악하는 단계입니다.

  • 계좌 조회: 주문 가능한 예수금, 보유 종목의 수익률 확인
  • 시세 조회: 타겟 종목(예: 삼성전자)의 현재가, 호가 잔량, 차트 데이터 수집 (GET 요청)
⬇

3 전략 및 알고리즘 판단 (Strategy)

가져온 데이터를 바탕으로 파이썬 내부에서 논리적 계산을 수행하여 매매 여부를 결정합니다. (통신 없음)

  • 예시: "현재가가 이동평균선을 돌파했는가?" -> True (매수 결정)
⬇

4 주문 실행 (Order Execution)

매수/매도 결론이 났다면, 증권사 서버에 주문 명령을 전송하여 거래를 성사시킵니다.

  • 동작: 계좌번호, 종목코드, 주문수량 등을 포장하여 서버로 전송 (POST 요청)
  • 결과: 주문 접수 번호를 파이썬으로 반환
⬇

5 모니터링 및 루프 (Monitoring & Loop)

프로그램이 종료될 때까지 2단계 ~ 4단계를 무한히 반복하며 체결 상태를 확인하고 에러를 관리합니다.

제 2부: API 통신 매커니즘 (미시적 원리)

GET 시세 조회 (데이터 읽기)

특징: 서버에 저장된 데이터를 가져오기만 하는 요청입니다. 주소(URL) 뒤에 필요한 정보를 나열합니다. (파이프라인 2단계 적용) 
// 가상 주소 (Request URL)
[https://openapi.kiwoom.com/uapi/v1/quotations/inquire-price](https://openapi.kiwoom.com/uapi/v1/quotations/inquire-price)
?FID_COND_MRKT_DIV_CODE=J           // J: 주식시장
&FID_INPUT_ISCD=005930                  // 005930: 삼성전자

// 서버 응답 데이터 (Response JSON)
{
    "rt_cd": "0",                       // 0: 성공
    "msg1": "정상 처리되었습니다",
    "output": {
        "stck_prpr": "78500",           // 현재가
        "acml_vol": "1245000"           // 누적 거래량
    }
}

POST 매수/매도 주문 (명령 내리기)

특징: 서버의 상태를 변경하는 요청입니다. 민감한 정보는 주소에 노출하지 않고 'Body' 영역에 숨겨 보냅니다. (파이프라인 1, 4단계 적용) 
// 보내는 데이터 (Request Body JSON)
{
    "CANO": "12345678",                 // 계좌번호 8자리
    "PDNO": "005930",                   // 종목코드
    "ORD_DVSN": "00",                   // 00: 지정가
    "ORD_QTY": "10",                    // 주문 수량
    "ORD_UNPR": "78000"                 // 주문 가격
}

// 주문 결과 응답 (Response JSON)
{
    "rt_cd": "0",
    "msg1": "주문이 성공적으로 접수되었습니다",
    "output": {
        "ODNO": "0000000123",           // 주문 번호
        "ORD_TMD": "103015"             // 체결 시각
    }
}
항목 GET (조회) POST (명령)
목적 데이터 읽기 데이터 쓰기/변경
보안성 낮음 (파라미터 노출) 높음 (Body에 암호화)
